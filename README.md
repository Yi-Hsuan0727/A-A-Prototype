# Handoff: Ascenzi & Associates Marketing Website

## Overview
Full marketing website for Ascenzi & Associates, a consultancy for firms entering U.S. advanced manufacturing construction (talent acquisition, licensing, U.S. market entry, and supporting/growth services). Bilingual (English / Traditional Chinese). Includes Home, About, four Service pages, Insight list + post template, and shared header / footer / contact-form components.

## About the Design Files
The files in this bundle (`.dc.html`) are **design references built in an HTML prototyping tool** — they render live in a browser but are not production code to copy verbatim. Recreate these designs in the target codebase's existing framework (React, Vue, etc.), or choose the most appropriate stack if none exists yet, using the codebase's own component/state patterns.

## Fidelity
**High-fidelity.** Colors, type, spacing, and copy are final as designed. Recreate pixel-accurately. Both language versions of every string live in the page's `<script data-dc-script>` block (`T = { en: {…}, zh: {…} }` plus per-list data) — treat those objects as the copy deck for both locales.

## Design Tokens
- **Primary blue:** `#0028FF` (hover `#001FBF`, active `#0018A0`)
- **Ink / near-black:** `#0B0B0B`
- **Body text (dark bg):** `#CDD4DB` / `#A8B0BA` (secondary)
- **Body text (light bg):** `#33383F` (primary) / `#4A5057` (secondary) / `#6E7373` (tertiary/labels)
- **Hairline borders:** `#E2E5EA` (light), `#33383F` / `#2A313A` / `#22262E` (dark)
- **Light tint fill:** `#EEF1FF` (info/highlight boxes)
- **Fonts:** Questrial (body/headings), IBM Plex Mono (labels, kickers, uppercase micro-copy, mono numerals), **Noto Sans TC** (CJK fallback for the Traditional Chinese locale — listed after Questrial in every font stack so Latin glyphs stay Questrial) — all via Google Fonts
- **Radius:** 3px on buttons, cards, images, tags, modal
- **Package icons (Home):** Talent Acquisition = `icons/modular.svg` (isometric cube), Licensing = `icons/permitting.svg`, U.S. Market Entry = `icons/market.svg`, Supporting & Growth = `icons/labor.svg`; the blue CTA card uses `icons/all-services.svg`.
- **Grid gaps:** 1px "seam" grids (background:#E2E5EA showing through) are used throughout for card/step lists
- **CTA grid background:** blue sections use a repeating-linear-gradient grid pattern: `repeating-linear-gradient(0deg, rgba(255,255,255,0.16) 0 1px, transparent 1px 14px)` (and 90deg variant) over `#0028FF`
- **Chinese typography:** when `<html lang="zh-Hant">`, headings drop their negative letter-spacing (`html[lang="zh-Hant"] h1, h2, h3 { letter-spacing:0 }`). Everything else (sizes, line-heights, weights) is shared between locales.

## Language switch (EN / 繁中)
- **Globe icon + dropdown list** in the header (desktop: between the nav links and the Contact Us button; mobile: bottom of the hamburger menu). The trigger is a 40px bordered button (globe SVG · current code `EN`/`繁中` in mono 11px · chevron); clicking opens a white menu card (`1px #E2E5EA`, radius 3, 12/32px shadow) listing **English** and **繁體中文**, the active one in blue with a check mark. Closes on selection, mouse-leave, or Escape.
- State lives on each page (`state.lang`), passed down to the shared components as a `lang` prop. Resolution order: `?lang=zh|en` query param → `localStorage['aa_lang']` → `en`. Switching writes localStorage and sets `document.documentElement.lang` (`zh-Hant` / `en`), so the choice persists across page loads.
- Every visible string on every page has a `zh` variant, including the Insight sample posts, the service-page client-type tags, FAQ, survey, and the contact form.

## Screens / Views

### Home.dc.html
Hero (headline "A single point of contact for U.S. advanced manufacturing" + subhead + icon-led "Start a conversation" / "View services" buttons → `#capabilities`), "What we do" cards, road/progress SVG timeline, world-globe partner locations, an **auto-typed tagline**, services package grid (4 cards linking to service pages + a blue "Not sure which package fits? → Talk to us" card that opens the contact form), Insight preview (3 cards), **"Become our partner" block** (kicker + H2 + body + blue "Become a partner →" button that opens the shared modal in **partner mode**, all in white text over a full-opacity dark photo background, beside a 2×2 icon grid of partner types: Academic (graduation cap) / Institutional (columned building) / Professional (briefcase) / Specialist (wrench) — the icon cards stay white with dark text/icons, no card numbers), FAQ accordion (5 questions, final copy), sector-focus banner, contact CTA section (enquiry button + phone + Phoenix office — no scheduling link, no email), shared footer and the shared contact modal (the hero "Start a conversation" CTA opens the 2-step enquiry; the former 3-question survey modal is removed).

- **Hero section height:** the `#top` section is `min-height:calc(100vh - 76px)` (flex-centered) — full viewport height minus the 76px sticky header — so the hero content fills exactly the remaining visible viewport on load, with no extra scroll needed to see the header at the same time.
- **Hero photo mask:** the masked logo-shaped photo carousel is measured live against the hero text column beside it (via a `ref` + `getBoundingClientRect()`, rechecked on mount, on resize, and a few times as web fonts settle) and kept at **the same height** as the text (a 360px floor before the first measurement lands), rather than relying on a viewport-based `clamp()`. The mask now uses the vector `icons/logo-mark.svg` (was the raster `icons/logo-mark.png`) so it stays crisp at any size.
- **Typed tagline:** "Advanced manufacturing doesn't wait for the paperwork. Neither do we." no longer just fades in — it also **types out character-by-character** (28ms/char, with a blinking `|` cursor) the first time the section scrolls into view (a dedicated `IntersectionObserver` at 50% visibility), and never re-types once it has run once, even if the section scrolls out and back. The section's height never shifts as the text grows: an identical, `visibility:hidden` copy of the full sentence sits behind the animated one (same font, same wrapping) purely to hold the layout's height, so there is no jump between the empty starting state and the finished sentence.
- **Contact Us button** (header, both desktop and — icon-only — the mobile floating pill) and the hero's **"Start a conversation"** button share the same chat-bubble SVG glyph; **"View services"** carries a small 2×2 grid glyph (the same icon shape used for "the full picture" card on service pages' Why sections).
- **Partnership background:** a full-opacity `jonakoh-_-r5lbaK3fDaM-unsplash.jpg` (a dark blue particle-wave photo) fills the section, oversized (`top:-30%; height:160%`) and shifted via a live `translateY` tied to the section's own scroll position (`getBoundingClientRect().top`, clamped to ±one viewport height, ×0.12, folded into the same rAF/scroll loop that already drives the road-timeline animation) so it drifts more slowly than the foreground as you scroll — a parallax effect. The photo itself is toned down (`filter:brightness(0.42) saturate(0.9)`) with an additional `rgba(0,0,0,0.42)→rgba(0,0,0,0.58)` scrim over the whole section, so it reads as a dark, muted backdrop rather than a bright photo, and the body copy is lifted to `rgba(255,255,255,0.82)` for contrast. The section's kicker/heading stay white/light-gray; the four partner-type cards now have real spacing between them (`gap:16px`, each card individually bordered `1px solid #E2E5EA` + `border-radius:3px` instead of the old 1px hairline seam grid) and a **frosted-glass look** — `background:rgba(255,255,255,0.88)` with `backdrop-filter:blur(14px) saturate(1.3)` and a `rgba(255,255,255,0.4)` border, instead of a flat opaque white — so the dark photo behind subtly shows through each card.
- **Favicon:** every page's `<helmet>` carries `<link rel="icon" href="icons/favicon.png">` — a square, letterboxed version of the blue "AA" mark (the source `icons/logo-mark.png` is landscape, ~780×455; the favicon asset pads it onto a transparent square canvas instead of stretching it, so the logo's aspect ratio is preserved in the browser tab).
- **"What we do" cards:** the expanding bullet list under the open/hovered card sits on a **transparent** panel, not its own flat fill — the card's photo now has its own separate gradient overlay layer (bottom-anchored, independent of the photo layer beneath it) whose **height animates between two states**: closed/unhovered = a short `42%`-tall dark band pinned to the bottom of the card (so most of the photo above it stays clearly visible); open/hovered = it grows to `100%` of the card height (480ms ease), so the darkening visibly slides upward to cover the whole card and back down again on mouse-leave. The gradient's own bottom stop is always fully opaque `rgba(0,2,8,1)`, matching the (transparent) list panel's implied color, so there is no seam in either state.
- **Road/progress timeline:** the step-marker dots are recomputed every animation frame from the live scroll position, so the position-driving CSS `transition` on `left`/`top` was removed (only the opacity fade still transitions). Previously, a fast or reversed (scroll-up) flick could visibly interpolate the dot in a straight line between two curve points instead of following the curved SVG path; dots now always render at their exact computed point on the Bézier curve, in both scroll directions.

## Shared Components
Header, footer and contact form are **separate `.dc.html` components** imported by every page with `<dc-import name="…">`; the runtime fetches the sibling file. They are the single source of truth for nav, footer and form markup and copy — recreate each once in the target codebase.

**SiteHeader.dc.html** — props `lang`, `active` (`home|about|services|insight`), `active-package` (`talent|licensing|market|growth`, service pages only), `on-set-lang(lang)`, `on-contact()`.
- **Sticky to the top of the viewport on every page** (the `<dc-import>` host carries `position:sticky; top:0; z-index:50`; page roots use `overflow-x:clip`, not `hidden`, so sticky keeps working). At the top of the page the bar is solid `#FFFFFF` with a `#E2E5EA` hairline; once scrolled (>8px) it switches to a **translucent frosted-glass** state — `rgba(255,255,255,0.72)` + `backdrop-filter: blur(18px) saturate(1.4)`, hairline `rgba(11,11,11,0.08)`, 220ms transition. The open mobile menu always uses the solid state. 76px min height, 1360px content width.
- Desktop (>860px): logo · Home · About Us · **Services** (14px chevron-down SVG, rotates when open) · Insight · **🌐 EN ▾ language dropdown** · **Contact Us** (blue 13.5px button, `12px 22px`). Active nav item = blue text + blue bottom border.
- **Services dropdown:** hover *or* click on the trigger opens a **full-width white panel** (`#FFFFFF`, `position:absolute; top:100%`, 24px/48px soft shadow, `#E2E5EA` hairline) with a two-column layout: left = a hairline list of the four packages (no header label — `01`–`04` mono number in `#0028FF`, 18px title, 13.5px `#6E7373` one-liner, arrow); right = a 300px-tall image (radius 3) with a strong bottom gradient (`rgba(4,7,20,0)` → `0.42` at 45% → `0.96` at 100%) so the package title stays legible over any photo (there is no small "Service package" caption above the title — just the title itself). Hovering/focusing a row highlights it (blue `1px` inset border + blue title text, no background fill) and crossfades the image to that package (320ms). Panel closes on mouse-leave (120ms grace), Escape, or clicking the trigger again. There is **no Services overview page** — the trigger is a button, not a link.
- Mobile (≤860px): hamburger toggle; the menu lists Home, About Us, Services (tap to expand the four packages inline with one-liners), Insight, then the language control. The Contact Us button leaves the bar and becomes an **icon-only floating button at bottom-right**: 56px blue circle, 24px chat-bubble stroke icon, `aria-label` "Contact Us", `position:fixed; right/bottom: clamp(14px,3vw,24px)`, 8/28px blue shadow.

## Interactions & Behavior
- **Language switch:** see above. Sub-components re-render from the `lang` prop; the page owns persistence.
- **Services dropdown:** hover-open with a 120ms close grace, click-to-toggle for touch, Escape to close, per-row hover swaps the side image.
- **Language dropdown:** click the globe button to open the list; pick or Escape closes it immediately. Mouse-leave closes it on a **180ms grace timer** (re-entering the trigger or the menu itself cancels the pending close), the same debounced pattern the Services dropdown already used — without it, the small gap between the trigger button and the menu below it made the menu fold before the cursor could reach an option.
- **Contact modal:** opened in contact mode from the header Contact Us (desktop button / mobile floating icon button), Home hero "Start a conversation", service/About/Insight enquiry CTAs, and Home's blue package card; opened in partner mode from Home's "Become a partner". Submit shows a static confirmation (no submission wired up).
- **Insight filters:** category pills + keyword search, combined; pagination resets on change.
- **Package cards / "what we do" cards (Home), and the "Other services" cards on all 4 service pages:** hover (or focus) reveals the item list and collapses the background photo to 0 height, as before — the same interaction now runs identically on both Home's package grid and each service page's "Other services" cards.
- **Sticky header:** solid at rest, translucent glass once scrolled (see Shared Components).
- **Reveal-on-scroll**, road timeline and globe animation on Home are unchanged.

## Assets
All images are under `uploads/` (stock/placeholder photography — replace with licensed final assets before production) and icons under `icons/` (mask-based monochrome SVG icons, tinted via `background-color` + `mask-image`). `icons/favicon.png` is a generated square, letterboxed version of `icons/logo-mark.png` (transparent padding added so the mark's aspect ratio isn't distorted by the browser's square favicon slot) — regenerate it the same way if the source mark changes. These must stay at the bundle root — the `.dc.html` files reference them as plain relative paths (`uploads/…`, `icons/…`), so moving them into a subfolder breaks every image. The shared components (`SiteHeader`, `SiteFooter`, `ContactModal`) must also stay next to the pages: `dc-import` resolves them as siblings.
- **`uploads/thumbs/`:** downsized, more heavily compressed copies of the source photos (resized so the long edge is 900px, JPEG quality ~68) used everywhere a photo displays small — Home's package cards (`#capabilities`) and their Other-services equivalents on the 4 service pages, the header's Services dropdown preview photo, and every Insight/Home article thumbnail. The originals (several MB, 3000-9500px on a side straight from Unsplash) were being served at 160-300px display heights; the same files are still used at full resolution wherever they appear large (hero photos, the About page image, the partnership section's parallax background) — only the small-thumbnail usages were repointed at `uploads/thumbs/`. Regenerate a thumb the same way (resize long edge to 900px, re-encode ~68 quality) if a source photo is replaced.

## Previewing Locally
Serve the folder over HTTP (e.g. `python3 -m http.server`, or a Live Server extension) and open any page `.dc.html` file. `support.js` is the prototyping tool's runtime — it must sit next to the HTML files, or the pages render as raw markup with visible `{{ binding }}` placeholders and every modal expanded at once. Opening the files directly via `file://` will not work (the shared components are fetched over HTTP). Append `?lang=zh` to any page URL to preview the Traditional Chinese version.
